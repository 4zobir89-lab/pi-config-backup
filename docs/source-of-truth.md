# Source of Truth and Deployment Boundary

## القرار المعتمد

يُعد مستودع `pi-config-backup` مصدر الحقيقة **للتكوين القابل للإصدار**، بينما يُعد `/root/.pi` نسخة تشغيلية منشورة على جهاز Pi. لا تُعتبر النسخة الحية مصدرًا للتعديلات، ولا تُنسخ منها ملفات الاعتماد أو الجلسات إلى GitHub.

| الطبقة | المصدر المعتمد | طبيعتها | سياسة التعديل |
|---|---|---|---|
| تعليمات Pi وECC | `pi/agent/AGENTS.md` والملفات المرتبطة | قابلة للإصدار | تعدّل في المستودع ثم تُراجع |
| طبقة Nova | `pi/agent/nova/` | Blueprint/عقود تصميم | لا تُعامل كـ Runtime فعلي |
| إعدادات النماذج | `pi/agent/settings.json` و`pi/agent/models.json` | إعدادات نشر حساسة | لا تُدمج حيًا إلا بخطة واختبار وRollback |
| Pi الحي | `/root/.pi` | Deployment mirror | قراءة ومقارنة، لا تعديل عشوائي |
| الأسرار والجلسات | خارج المستودع ومدير أسرار/بيئة التشغيل | Runtime state | ممنوع رفعها أو طباعتها |

## ما أثبته فحص Pi الحي

الحزمة المنقحة المرفوعة في 21 أغسطس 2026 تحتوي 907 ملفات، منها 150 ملفًا في `nova/` و15 Plugin. شجرة Nova في الحزمة مطابقة للمستودع، وامتداد Penpot مطابق أيضًا. لا يوجد داخل `nova/` ملف تنفيذي JavaScript أو TypeScript أو Runtime Adapter؛ الموجود JSON وYAML وMarkdown وعقود Schemas فقط.

إعدادات Pi الحية ليست مطابقة للإعدادات المقترحة في المستودع. يحتفظ Pi الحي بـ `opencode/hy3-free`، وبمسارات `/root/.pi`، وبقيم AOW والتوجيه القديمة، وبمراجع مزودين تحتوي قيمًا حرفية في البيئة الحية. أما المستودع فيحتوي إعدادات مستهدفة تستخدم `freemodel/gpt-5.4-mini` ومراجع متغيرات البيئة ومسارات محمولة. هذا الاختلاف مقصود حاليًا لتجنب كسر Pi قبل اختبار البدائل وتدوير المفاتيح.

## الحالة السلوكية

> **ECC Active — Nova Passive — Runtime Adapter Missing**

وجود `nova.enabled` أو `workflow.json` لا يثبت أن Pi ينفذ Orchestration. طبقة Nova الحالية هي Blueprint منظم، بينما السلوك الفعلي يأتي من Pi Runtime وتعليمات ECC. لا يجوز وصف المراحل العشر بأنها تعمل فعليًا قبل إنشاء Adapter واختباره.

## قواعد العمل من الآن

لا يُعدّل `/root/.pi` مباشرة إلا ضمن عملية نشر موثقة، وبعد أخذ نسخة احتياطية وتشغيل اختبارات قبول وRollback. لا تُزامن `models.json` الحي تلقائيًا مع المستودع؛ يجب أولًا تدوير الأسرار، اختبار المزود البديل، ثم تنفيذ تغيير صغير قابل للتراجع. ولا يبدأ Runtime Adapter قبل اعتماد مواصفة واحدة ونجاح Spike يثبت آلية استدعاء الوكلاء.
