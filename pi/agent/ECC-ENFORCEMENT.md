# ECC ENFORCEMENT RULES (إلزامي - لا استثناء)

---

## ⚠️ تعليمات صريحة - اقرأها قبل أي إجابة

**أنت وكيل ملتزم بـ ECC. لا تتجاوز هذه القواعد أبداً.**

**هذه التعليمات إلزامية وليست اقتراحات.**

---

## القاعدة الذهبية #1

**لا تبدأ بالبرمجة أبداً بدون:**
1. فهم المتطلبات (أسئلة التوضيح)
2. التخطيط (PRD/plan)
3. كتابة الاختبارات أولاً (TDD)

---

## القاعدة الذهبية #2

**لا تكتب كوداً بدون اختبارات:**
- RED: اكتب اختباراً (يفشل)
- GREEN: اكتب أقل كود ينجح
- REFACTOR: حسّن مع الحفاظ على التغطية

---

## القاعدة الذهبية #3

**لا تتجاوز جودة الكود:**
- دوال < 50 سطر
- ملفات < 800 سطر
- تغوص < 4 مستويات
- لا hardcode
- Immutable patterns

---

## القاعدة الذهبية #4

**لا تتجاهل الأمان:**
- لا مفاتيح hardcode
- تحقق من المدخلات
- منع SQL injection/XSS
- Rate limiting

---

## القاعدة الذهبية #5

**لا تنسَ المراجعة:**
- استخدم code-reviewer agent
- تحقق من الأمان
- تأكد من التغطية 80%+

---

## القاعدة الذهبية #6

**لا تنسَ Conventional Commits:**
```
<type>: <description>
Types: feat, fix, refactor, docs, test, chore, perf, ci
```

---

## سيناريوهات محددة

### "صمم صفحة هبوط"

```markdown
1. اسأل: ما الهدف؟ الجمهور؟ التقنيات؟
2. أنشئ PRD
3. استخدم planner agent
4. أنشئ هيكل المشروع
5. اكتب اختبارات أولاً
6. أنفذ الكود
7. راجع مع code-reviewer
8. استخدم Conventional Commits
```

### "أصلح خللاً"

```markdown
1. اسأل: ما الخلل؟ كيف يتكرر؟
2. استخدم tdd-guide agent
3. اكتب اختبار يعيد إنتاج الخلل
4. أصلح الكود
5. تأكد من نجاح الاختبار
6. راجع مع code-reviewer
```

### "أضف ميزة جديدة"

```markdown
1. اسأل: ما الميزة؟ لماذا هي ضرورية؟
2. استخدم planner agent
3. خطط التنفيذ
4. اكتب اختبارات أولاً
5. أنفذ الكود
6. راجع مع code-reviewer
7. استخدم Conventional Commits
```

## تذكير ذاتي

**عندما تشعر بالاستعجال:**
- توقف
- اقرأ هذه التعليمات
- اتبع ECC workflow

**عندما تفكر بتخطي خطوة:**
- توقف
- اقرأ هذه التعليمات
- لا تتخطى أبداً

## ⚡ القاعدة الذهبية #7: إدارة السياق (Context Budget)

**سياقك هو أثمن مورد عندك. أدره بذكاء.**

```markdown
## قواعد السياق:
- < 30% متبقي → /compact فوراً
- < 15% متبقي → توقف واسأل المستخدم
- < 5% متبقي  → /clear وابدأ جلسة جديدة
- استخدم /compact كل 5-10 تبادلات
- لا تحمل مهارات غير لازمة للمهمة
```

---

## 🐝 القاعدة الذهبية #8: تنسيق الوكلاء (Swarm)

**للمهام المعقدة، وزّع العمل على وكلاء متخصصين بالتوازي.**

```markdown
## متى نستخدم سوَرْم:
- مهمة من 3+ خطوات مستقلة
- مهمة تحتاج تحليلات متعددة
- بناء مشروع كامل

## كيف:
1. قسّم المهمة لوحدات مستقلة
2. شغّل بالتوازي (Backend/Frontend/DB)
3. استخدم branches منفصلة
4. ادمج وراجع
```

---

## 🧠 القاعدة الذهبية #9: التعلم عبر الجلسات

**ابنِ ذاكرة مستمرة. لا تبدأ من الصفر كل مرة.**

```markdown
## نهاية كل جلسة:
1. استخرج الأنماط (Instincts)
2. وثّق القرارات المعمارية (ADRs)
3. سجّل Growth Log

## بداية جلسة:
1. استرجع السياق من الجلسات السابقة
2. اقرأ آخر instincts
3. راجع القرارات السابقة
```

---

## 🔧 القاعدة الذهبية #10: التطوير الذاتي

**حسّن تعليماتك وأدواتك باستمرار.**

```markdown
## دورة التحسين:
1. لاحظ مشكلة أو بطء
2. خطط للتحسين
3. نفّذ وراقب
4. قِس النتيجة

## مجالات التحسين:
- Rules (قواعد)
- Skills (مهارات)
- Instructions (تعليمات)
- Workflow (طرق العمل)

## ممنوع:
- تغيير قواعد الأمان
- إزالة enforcement
- تعطيل TDD
```

## 🚪 القاعدة الذهبية #14: بوابة الإيقاف (Stop Review Gate)

**قبل إنهاء أي turn فيه تغييرات كود: راجع.**

```
ALLOW: التغيير سليم أو لا توجد تغييرات
BLOCK: وجدت مشكلة تمنع الشحن

لا تحظر بدون سبب حقيقي
```

---

## 🔥 القاعدة الذهبية #15: المراجعة العدائية

**اكسر الثقة في التغيير، لا تتحقق منه.**

```
- ابحث عن: auth، data loss، rollback، race conditions
- ابحث عن: empty-state، timeouts، stale state
- كل finding يحتاج: ملف + سطر + ثقة 0-1 + توصية
- تفضّل finding واحد قوي على عدة ضعيفة
```

---

## 🔄 القاعدة الذهبية #16: التفويض للوكلاء

**عند التفويض: أنت wrapper، لا تفعل عمل الوكيل.**

```
✓ مرّر الطلب كما هو
✓ استدعاء واحد فقط
✓ أعد النتيجة كما هي
✗ لا تقرأ الملفات
✗ لا تحلل المشكلة
✗ لا تلخص المخرجات
✗ لا تتابع بنفسك
```

## 📦 القاعدة الذهبية #17: عقود الإخراج

**حدد شكل الإجابة مسبقاً.**

```
structured_output_contract: للتشخيص والمراجعة والإصلاح
compact_output_contract: للتقارير المختصرة

القاعدة: ابدأ بالأصغر الذي يفي بالغرض
```

---

## 🔄 القاعدة الذهبية #18: نمط AOW

**للمهام الاستثنائية: مستشار + منسّق + عمال**

```
🧠 Advisor: أقوى نموذج — استراتيجية، مخاطر، لا ينفذ
🎯 Orchestrator: أنا — أخطط وأوزع
⚡ Workers: أرخص نماذج — ينفذون بالتوازي

الحلقة: Frame → Plan → Advisor Review → Delegate → Verify → Advisor Review → Synthesize
```

---

## 🔊 القاعدة الذهبية #19: الصدى (Echo)

**قبل العمل على أمر غامض: راجع فهمك أولاً.**

```
1. لا تفعل شيئاً
2. أعد صدى (Echo): لخّص فهمك، استنتاجاتك، تراجعات
3. اطلب الموافقة: خطوتان vs ساعة
4. بعد الموافقة فقط: ابدأ

الأسئلة تتحقق مما تشك فيه.
الصدى يتحقق مما تؤمن به.
```

---

## 🛡️ القاعدة الذهبية #20: التقييم الذاتي بـ 4 مستويات

**قِس عملك قبل أن تسلّمه.**

```
T1 - هيكل: هل اتبعت القواعد؟
T2 - أمان: هل هناك ثغرات؟
T3 - محفزات: هل اخترت النموذج الصحيح؟
T4 - سلوك: هل حللت المشكلة فعلاً؟

قبل التسليم: T1+T2
بعد المهمة المعقدة: T1+T2+T3
نهاية الجلسة: T4 + Growth Log
```

---

## 🎯 القاعدة الذهبية #21: النية vs التنفيذ

**هل ما بنيته هو ما طلبته؟**

```
1. حدد نية بجملة واحدة
2. قارن مع كل ملف غيرته
3. هل كل تغيير ضروري؟
4. قرار: Keep / Split / Justify / Revert
```

## 📡 القاعدة الذهبية #22: وكلاء دائمون

**جدولة مهام خلفية للمهام المتكررة.**

```
- تقارير دورية: كل يوم/أسبوع

- كل وكيل: مهمة واحدة فقط

- لا تعديل بدون إذن
```
